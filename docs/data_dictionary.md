# Data Dictionary

## Overview

This document explains the datasets, tables, columns, and calculated metrics used in the **DiscoverIQ — Ecommerce Product Discovery & Conversion Analytics Platform** project.

The project uses the public **REES46 Ecommerce Behavior Dataset** from Kaggle and transforms raw ecommerce event data into analytical tables for SQL analysis and Power BI dashboarding.

The original raw data contains user-product interaction events such as:

```text
view → cart → purchase
```

These events were cleaned, optimized, aggregated, and exported into BI-ready tables.

---

## 1. Raw Dataset Columns

The original dataset contains event-level ecommerce data.

| Column          | Data Type | Description                       | Example                      |
| --------------- | --------- | --------------------------------- | ---------------------------- |
| `event_time`    | datetime  | Timestamp when the event occurred | `2019-10-01 00:00:00 UTC`    |
| `event_type`    | string    | Type of user event                | `view`, `cart`, `purchase`   |
| `product_id`    | integer   | Unique product identifier         | `1004856`                    |
| `category_id`   | integer   | Encoded category identifier       | `2053013555631882655`        |
| `category_code` | string    | Human-readable category path      | `electronics.smartphone`     |
| `brand`         | string    | Product brand name                | `samsung`, `apple`, `xiaomi` |
| `price`         | float     | Product price in USD              | `127.27`                     |
| `user_id`       | integer   | Unique user identifier            | `555465000`                  |
| `user_session`  | string    | Unique session identifier         | `abc123-session-guid`        |

---

## 2. Engineered Columns

During cleaning and feature engineering, additional columns were created to support time-based, category-based, and product-level analysis.

| Column        | Source                | Description                   | Purpose                               |
| ------------- | --------------------- | ----------------------------- | ------------------------------------- |
| `date`        | `event_time`          | Extracted date from timestamp | Daily trend analysis                  |
| `hour`        | `event_time`          | Hour of event                 | Hourly behavior analysis              |
| `day_of_week` | `event_time`          | Day name or day number        | Day-of-week performance               |
| `week_number` | `event_time`          | Week number within month/year | Weekly trend analysis                 |
| `month`       | Derived / hardcoded   | Month label                   | October vs November comparison        |
| `category_l1` | `category_code` split | Top-level category            | Category performance                  |
| `category_l2` | `category_code` split | Second-level category         | Sub-category analysis                 |
| `price_tier`  | `price` bucket        | Product price segment         | Budget, mid, premium, luxury analysis |

---

## 3. Price Tier Definition

Products were grouped into price tiers to analyze how different price ranges behave.

| Price Tier | Price Range | Meaning             |
| ---------- | ----------: | ------------------- |
| `budget`   |      $0–$50 | Low-price products  |
| `mid`      |    $50–$200 | Mid-range products  |
| `premium`  |   $200–$500 | High-value products |
| `luxury`   |       $500+ | Expensive products  |

The raw event data was transformed into combined analytical tables for October and November.

# `combined_session_summary`

## Purpose

Session-level table used for funnel, revenue, daily trend, day-of-week, and executive KPI analysis.

Each row represents one user session.

## Grain

```text
One row = one user session
```

## Columns

| Column         | Description                                             |
| -------------- | ------------------------------------------------------- |
| `user_session` | Unique session identifier                               |
| `user_id`      | Unique user identifier                                  |
| `date`         | Session date                                            |
| `week_number`  | Week number                                             |
| `day_of_week`  | Day of week                                             |
| `viewed`       | 1 if session had at least one product view, else 0      |
| `carted`       | 1 if session had at least one add-to-cart event, else 0 |
| `purchased`    | 1 if session had at least one purchase, else 0          |
| `revenue`      | Total purchase revenue generated by session             |
| `total_events` | Total number of events in the session                   |
| `month`        | October or November                                     |

## Main Use Cases

* Total sessions
* Total users
* Product view sessions
* Cart sessions
* Purchase sessions
* Revenue
* Funnel drop-off
* Conversion rate
* Cart abandonment
* Daily trend
* Day-of-week analysis

## 6. Key Calculated Metrics

This section explains the main calculations used throughout the project.

---

## Total Sessions

```text
Total sessions = count of unique user_session
```

Measures total user visits or browsing sessions.

---

## Total Users

```text
Total users = count of unique user_id
```

Measures unique users.

---

## View Sessions

```text
View sessions = sessions where viewed = 1
```

Measures sessions where the user viewed at least one product.

---

## Cart Sessions

```text
Cart sessions = sessions where carted = 1
```

Measures sessions where the user added at least one product to cart.

---

## Purchase Sessions

```text
Purchase sessions = sessions where purchased = 1
```

Measures sessions where the user completed at least one purchase.

---

## Total Revenue

```text
Total revenue = sum of purchase price values
```

Measures total sales revenue.

---

## View-to-Cart Rate

```text
View-to-cart rate = cart_sessions / view_sessions * 100
```

Measures how many product-view sessions moved to cart.

---

## Cart-to-Purchase Rate

```text
Cart-to-purchase rate = purchase_sessions / cart_sessions * 100
```

Measures how many cart sessions became purchase sessions.

---

## Conversion Rate

```text
Conversion rate = purchase_sessions / view_sessions * 100
```

Measures how many product-view sessions became purchase sessions.

---

## Cart Abandonment Rate

```text
Cart abandonment rate = (cart_sessions - purchase_sessions) / cart_sessions * 100
```

Measures how many cart sessions did not convert into purchase sessions.

---

## Revenue per Session

```text
Revenue per session = total_revenue / total_sessions
```

Measures average revenue generated per session.

---

## Revenue per User

```text
Revenue per user = total_revenue / total_users
```

Measures average revenue generated per user.

---

## Revenue per View

```text
Revenue per view = total_revenue / view_sessions
```

Measures how much revenue is generated from product-view sessions.

---

## Cart Rate

```text
Cart rate = total_carts / total_views * 100
```

Measures product-level add-to-cart behavior.

---

## Product Conversion Rate

```text
Product conversion rate = total_purchases / total_views * 100
```

Measures product-level purchase conversion.

---

## Product Cart-to-Purchase Rate

```text
Product cart-to-purchase rate = total_purchases / total_carts * 100
```

Measures how many cart actions became purchase actions at product level.

## 7. Important Notes

### Percentage Fields

Percentage columns are stored as percentage values, not decimals.

Example:

```text
2.82 means 2.82%, not 0.0282
```

In Power BI, these values should not be multiplied by 100 again.

### Data Limitation

Because the original dataset was too large, stratified sampling was used.

This preserves the overall event distribution but can create some session-level artifacts. For example, a sampled session may contain a purchase event but miss the earlier cart event if the cart row was not included in the sample.

This limitation is documented in the project and should be considered when interpreting session-level cart abandonment metrics.
